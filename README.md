# Introduction

Algorithm Visualizer is a client-side web application that makes abstract algorithm
behaviour tangible by animating it in the browser. It covers two categories of
algorithms:

- **Sorting** – Bubble Sort, Selection Sort, Quick Sort, and Merge Sort, rendered as
  an animated bar chart built with Recharts.
- **Pathfinding** – Breadth-First Search (BFS) on a 2D tile grid, where a start tile
  and an end tile are connected through a shortest path while optionally navigating
  walls generated by a Binary Tree maze.

The project is written in **React 19 + TypeScript + Vite**, uses **Tailwind CSS** and
**shadcn/ui** for styling, and **Recharts** for the sorting charts. Routing is handled
by **react-router v7**.

# Problem Statement

Static textbook descriptions of algorithms fail to convey *how* and *why* an algorithm
behaves the way it does. Learners frequently struggle to reason about:

1. **Order of operations** – e.g., which elements are compared or swapped first.
2. **Performance trade-offs** – how the number of comparisons/swaps grows with input.
3. **Correctness** – why a greedy or recursive strategy produces the right answer.

The goal of this project is to build a lightweight, interactive tool that:

- Animates sorting algorithms over a randomly generated array of bars, while counting
  live comparisons and swaps.
- Animates a pathfinding algorithm (BFS) across a grid, marking explored tiles before
  revealing the final shortest path.
- Lets users generate maze walls, draw custom walls, and control animation speed so
  they can observe behaviour at their own pace.

# Methodology

## System Design

The application is a single-page app (SPA) with three logical layers:

1. **Routing & Pages** (`src/App.tsx`, `src/pages/`)
   - `BrowserRouter` from `react-router` maps each algorithm to its own route:
     - `/` — home page
     - `/sort/bubble-sort`, `/sort/selection-sort`, `/sort/quick-sort`, `/sort/merge-sort`
     - `/pathfinding/bfs`
     - `/*` — 404 page
   - A shared `Layout` wraps every page with a sticky `Header` and a `Footer`.

2. **State Management** (`src/context/`)
   - `PathFindingContext` – holds the grid, selected algorithm, selected maze, and a
     `isGraphVisualized` flag.
   - `TileContext` – holds the start and end tiles.
   - `SpeedContext` – holds the animation speed (`0.5`, `1`, or `2` multiplier).
   - Dedicated hooks (`usePathfinding`, `useTile`, `useSpeed`) expose these contexts.

3. **Algorithm & Rendering** (`src/algorithms/`, `src/lib/`, `src/components/`)
   - Pure algorithm implementations live in `src/algorithms/`.
   - Grid helpers, animation scheduling, and maze utilities live in `src/lib/`.
   - Presentational components (charts, grid, tiles, buttons) live in `src/components/`.

Because the sorting and pathfinding tools are independent, they are composed by their
own wrapper components (`SortingVisualizer` and `PathfindingVisualizer`) rather than a
single monolithic visualizer.

## Algorithm Selection

**Sorting** – four classic algorithms were chosen to represent different complexity
classes and strategies:

| Algorithm        | Strategy                | Route                | Source                                         |
| ---------------- | ----------------------- | -------------------- | ---------------------------------------------- |
| Bubble Sort      | Comparison, iterative   | `/sort/bubble-sort`  | `src/components/sort/BubbleSortGraph.tsx`       |
| Selection Sort   | Selection, iterative    | `/sort/selection-sort` | `src/components/sort/SelectionSortGraph.tsx`   |
| Quick Sort       | Divide & conquer (pivot)| `/sort/quick-sort`   | `src/components/sort/QuickSortGraph.tsx`       |
| Merge Sort       | Divide & conquer (merge)| `/sort/merge-sort`   | `src/components/sort/MergeSortGraph.tsx`       |

**Pathfinding** – the `PathFindingAlgorithmType` union defines four algorithms
(`DIJKSTRA`, `A_STAR`, `BFS`, `DFS`). **BFS** is currently implemented
(`src/algorithms/bfs.ts`) and exposed in the UI, since BFS guarantees the shortest path
in an unweighted grid and is the pedagogical baseline from which the others can be added.

**Maze generation** – a **Binary Tree** maze is implemented
(`src/algorithms/maze/binaryTree.ts`). The `MazeType` union also reserves
`RECURSIVE_DIVISION` for future work.

## Visualization Approach

The visualization relies on React state for data and **CSS-class mutations driven by
timers** for animation:

- **Sorting:** the array is stored in component state (`data`). After each comparison
  or swap the state is re-set (`setData([...arr])`) after a short `setTimeout` delay,
  causing Recharts to re-render the bars. Live counters for comparisons and swaps are
  updated alongside. A `playRef` boolean lets the user pause/resume by breaking the
  loop between frames.
- **Pathfinding:** tiles carry booleans (`isTraversed`, `isPath`, `isWall`). After BFS
  returns the ordered list of traversed tiles and the final path, `animatePath` schedules
  `setTimeout` callbacks that toggle CSS classes directly on the tile DOM elements
  (`tile-{row}-{col}`) — first the cyan traversal wave, then the green path overlay.
- **Speed control:** a multiplier (`0.5`/`1`/`2`) scales every sleep/delay value so
  Slow/Medium/Fast map directly to animation pacing.

## User Interaction Flow

**Sorting page**
1. Page loads and generates 100 random bars (height `1–500`).
2. The user picks an algorithm from the dropdown (navigates to its route) or clicks
   **Start**.
3. The chart animates while **Total Comparisons** and **Total Swaps** increment live.
4. The user can **Pause/Resume** or regenerate a fresh random array (**reset** button).
   If the array is already sorted, pressing Start regenerates it automatically.

**Pathfinding page**
1. A `43 × 79` grid renders with a green start tile at `(1,1)` and a red end tile at
   `(41,77)`.
2. The user may generate a **Binary Tree** maze or draw walls by clicking/dragging over
   the grid (start/end tiles are protected).
3. Choosing **Play** runs BFS: traversed tiles flood cyan, then the shortest path is
   overlaid in green. Controls are disabled while the animation runs.

## Key Components

- **`SortingVisualizer.tsx`** — maps an algorithm key (`'bubblesort' | 'quicksort' |
  'mergesort' | 'selectionsort'`) to its graph component and renders it in a shared,
  centered container.
- **`BubbleSortGraph.tsx` / `QuickSortGraph.tsx` / `MergeSortGraph.tsx` /
  `SelectionSortGraph.tsx`** — each implements its own sort routine as an async
  function that mutates a copy of the data array, updates comparison/swap counters,
  and triggers a re-render on every step. All four share the same `Card` + `Recharts`
  `BarChart` layout.
- **`Grid.tsx`** — renders `MAX_ROWS × MAX_COLS` tiles and implements click-drag wall
  drawing via `onMouseDown` / `onMouseEnter` / `onMouseUp` handlers, guarded by a
  `isVisualizationRunningRef`. Tile size adapts to the viewport width.
- **`Tile.tsx`** — resolves the correct CSS style per tile state
  (start / end / wall / path / traversed) and exposes mouse handlers.
- **`PlayBFSBtn.tsx`** — runs `bfs()`, then `animatePath()` with timing derived from
  the current speed, and releases the disabled state once the animation completes.
- **`SelectMazeButton.tsx`** — dispatches maze generation via `GenerateMazeAlgorithms`
  or resets the grid when `NONE` is selected.

## Sorting Algorithm Example

The **Bubble Sort** visualizer (`src/components/sort/BubbleSortGraph.tsx`) is a good
illustration of the pattern shared by all four sort graphs:

```ts
const BubbleSort = async (arr: Data[], length: number) => {
  for (let i = 0; i < length && playRef.current; i++) {
    let swapped = false
    for (let j = 0; j < length - i - 1 && playRef.current; j++) {
      setComparisons((prev) => prev + 1)          // count every comparison
      if (arr[j].height > arr[j + 1].height) {
        ;[arr[j], arr[j + 1]] = [arr[j + 1], arr[j]]
        swapped = true
        setSwap((prev) => prev + 1)               // count every swap
        await new Promise((resolve) => setTimeout(resolve, 15))
        setData([...arr])                         // re-render the bars
      }
    }
    if (!swapped) break                           // early exit on sorted run
  }
}
```

Key points:

- `playRef.current` gates every loop iteration, so toggling it pauses/resumes instantly.
- The `isAlreadySorted` helper detects an already-ordered array so the tool regenerates
  input instead of replaying a no-op.
- Recharts receives a fresh array reference per step, which drives the animation.

## Pathfinding Algorithm Example

**BFS** (`src/algorithms/bfs.ts`) operates on the `GridType` (a `TileType[][]`). Each
tile stores `row`, `col`, state flags, a `distance`, and a `parent` reference used to
reconstruct the shortest path by backtracking from the end tile.

```ts
while (unTraversed.length) {
  const tile = unTraversed.shift()!          // FIFO queue
  if (tile?.isWall) continue
  if (tile?.distance === Infinity) break
  tile.isTraversed = true
  traversedTiles.push(tile)
  if (isEqual(tile, endTile)) break
  const neighbors = getUntraversedNeighbors(grid, tile)
  for (const neighbour of neighbors) {
    if (!isInQueue(unTraversed, neighbour)) {
      neighbour.distance = tile.distance + 1
      neighbour.parent = tile
      unTraversed.push(neighbour)
    }
  }
}
```

- Neighbors are the four orthogonal cells (up / down / left / right), filtered to skip
  already-traversed tiles.
- Because BFS expands level by level, the first time the end tile is reached the
  recorded `parent` chain is a shortest path.
- The returned `{ traversedTiles, path }` feeds `animatePath`, which first colors every
  visited tile (cyan), then walks the path (green) after the traversal completes.

# Results & Interpretation

## Sorting Visual Output

Each sort page renders a `Recharts` bar chart of 100 bars. During execution:

- Bars jump and re-order step-by-step, mirroring the underlying loop.
- **Total Comparisons** and **Total Swaps** tick upward, making the efficiency gap
  between algorithms visible (e.g., Bubble/Selection perform far more work on large
  inputs than Quick/Merge).
- The **reset** button replaces the array with a fresh random one, allowing repeated
  trials to compare behavior.

## Pathfinding Visual Output

On the BFS page:

- A **cyan flood** propagates outward from the start tile, demonstrating BFS's
  level-by-level expansion over the `43 × 79` grid.
- Once the end tile is reached, a **green path** is drawn from start to end, proving the
  found route is minimal (fewest tiles).
- **Binary Tree** maze generation produces a deterministic, fully-connected maze, and
  user-drawn walls demonstrate that obstacles are honored and the shortest path routes
  around them.

# Conclusion

The project delivers a working interactive environment for learning and comparing
classic algorithms. Sorting is animated as a live bar chart with performance counters,
and pathfinding is animated on a grid with maze generation, wall drawing, and speed
controls — all within a clean, responsive shadcn/ui interface.

The architecture (context-based state, pure algorithm modules, and timer-driven
animation) makes it straightforward to extend: additional pathfinding algorithms
(Dijkstra, A*, DFS) are already reserved in the type system, and the
`RECURSIVE_DIVISION` maze is a planned follow-up.

## Flowcharts

High-level flow for each visualization:

```
[Render input] → [Run algorithm step] → [Update state/UI] → [Next step] → [Finish]
```

- Sorting: Generate random array → loop compare/swap (pause-checked) → re-render → done.
- Pathfinding: Build grid → (optional) generate maze / draw walls → run BFS → animate
  traversed tiles → animate path → re-enable controls.

## Time & Space Complexity

| Algorithm          | Best Time   | Average Time | Worst Time   | Space    |
| ------------------ | ----------- | ------------ | ------------ | -------- |
| Bubble Sort        | O(n)        | O(n²)        | O(n²)        | O(1)     |
| Selection Sort     | O(n²)       | O(n²)        | O(n²)        | O(1)     |
| Quick Sort         | O(n log n)  | O(n log n)   | O(n²)        | O(log n) |
| Merge Sort         | O(n log n)  | O(n log n)   | O(n log n)   | O(n)     |
| BFS (pathfinding)  | O(V + E)    | O(V + E)     | O(V + E)     | O(V)     |

Where `n` is the array size (100 bars) for sorting, and `V` / `E` are the grid tiles and
adjacencies for pathfinding.
